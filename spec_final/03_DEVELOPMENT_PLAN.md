# 1. 总体开发策略

目标不是一次性让 Codex “把整个系统写完”，而是把开发拆成可验证的 Phase 和 Task。

每个 Task 必须形成完整闭环：

```text
读取规格
→ 检查现状
→ 实现一个能力
→ 自动测试
→ 对应场景验收
→ 修复
→ 更新 DEV_STATUS
→ 自动进入下一个未完成 Task
```

只有当前 Phase Gate 通过，才允许进入下一 Phase。

## Phase 8 执行顺序与交付门槛

### 8.1 先做技术路线决策，不直接接 OCR

推荐路线：先接入本地可替换解析适配器，优先支持文本型 PDF 与 Excel；扫描件 OCR 作为第二个适配器，不把 OCR 结果直接当作事实，必须带页码、单元格/行号、置信度和人工复核状态。

不建议当前直接绑定某一家 OCR 服务，原因是项目尚未确定数据出境、费用、服务可用性和生产凭证管理。适配器接口先冻结，具体供应商后置。

### 8.2 TASK-0903 的实现拆分

1. `0903-a`：解析器接口与本地测试夹具
   - 输入：文件元数据、二进制内容、材料类型、客户上下文。
   - 输出：`ParsedMaterialResult`、字段证据、来源位置、警告和失败码。
   - 验收：同一文件重复解析必须幂等；失败不生成商品行；所有事实行都能追溯到文件位置。

2. `0903-b`：文本 PDF / Excel 解析器
   - 优先复用现有 `demo-generated` 的提取与复核规则，不改真实样本。
   - Excel 保留 sheet、原始行号、合并单元格和 UNKNOWN；PDF 保留页码和文本区域。
   - 验收：至少用 1 个真实文本 PDF、1 个真实 XLS/XLSX 完成“解析 → 材料批次 → 原始事实”的回归。

3. `0903-c`：解析失败和人工复核入口（页面状态闭环）
   - 解析超时、格式不支持、客户不确定、字段冲突分别展示，不合并成笼统失败。
   - 验收：失败任务可重试；重试不产生重复材料批次；人工复核前不能进入匹配；刷新后任务状态、失败原因和复核原因仍可见。

4. `0903-d`：真实文件执行接线（已完成）
   - 浏览器上传的文件内容进入本地可替换解析适配器；解析任务从待解析/解析中真实走到解析成功/解析失败/待人工复核。
   - 成功结果必须带内容指纹、材料类型、事实行和来源位置；失败不得生成商品池行、客户关系或匹配关系。
   - 验收：至少用一个真实文本 PDF 和一个真实 XLS/XLSX 完成上传元数据 → 解析任务 → 事实结果的端到端回归；扫描件继续返回 OCR_REQUIRED，不伪造成功。

### 8.3 TASK-0904～0905 的依赖关系

- `TASK-0904` 必须依赖 `TASK-0903` 的客户识别结果契约，不能在页面层另写客户识别逻辑。
- `TASK-0905` 必须至少覆盖：正常文件、重复文件、客户未知、解析失败、刷新恢复、跨客户拦截。
- 真实材料仍然只读；测试产物写入 `demo-generated` 或临时目录，不回写 `真实整单样本/`。

### 8.4 TASK-0905 的安全拆分

1. `0905-a`：表头驱动的委托事实转换
   - 只接受含明确中文表头的 Excel；按表头名映射品牌、型号、产地、数量等字段，不按列序猜测未知模板。
   - 转换结果先生成委托草稿；UNKNOWN 保持 UNKNOWN；每行保留原始 Sheet/行号和内容指纹。
   - 使用已确认客户，只与同客户商品池匹配。
2. `0905-b`：真实查货材料进入商品池
   - 当前真实查货材料主要为扫描 PDF，必须等 OCR/人工录入方案确认；不得从原始图片或参考结果反推商品行。
   - 在 OCR 决策前，只验收 `OCR_REQUIRED`、人工复核和“不进入商品池”。

# 14. 用户与 Codex 的短指令

## 开始项目

```text
按 spec/00_SPEC_INDEX.md 启动 Spec Coding。读取 DEV_STATUS 后，从当前第一个未完成 Task 开始，按 04_LOOP_ENGINEERING.md 连续执行所有未完成 Task；每个 Task 独立闭环并更新 DEV_STATUS，直到全部开发 Task 完成后停止。
```

## 继续开发

```text
继续当前开发 Loop。读取 DEV_STATUS，执行当前及后续 Phase 的下一个未完成 Task。每个 Task 完成实现、测试、场景验收、必要修复后更新 DEV_STATUS，并自动继续；直到全部开发 Task 完成、出现明确阻塞或用户要求暂停时停止。
```

## 连续完成当前 Phase（兼容旧指令）

该指令仍可使用，但现在默认采用跨 Phase 连续开发模式：

```text
连续执行当前 Phase。每个 Task 都必须独立完成测试和验收；当前 Phase Gate 通过后自动进入下一 Phase 的第一个未完成 Task，直到全部开发 Task 完成或触发停止条件。
```

# 15. 最终开发完成定义

项目不是以“所有页面都存在”为完成。

必须同时满足：

1. 02 Spec 关键 Case 通过；
2. 主演示 Playwright 链通过；
3. 六页状态真实联动；
4. 25 列最终核对单正确；
5. 多对多可追到原始查货行；
6. 增量更新不重建稳定结果；
7. 最终确认后商品核销且结果封版；
8. 无讲解走查可以自然理解核心流程。
