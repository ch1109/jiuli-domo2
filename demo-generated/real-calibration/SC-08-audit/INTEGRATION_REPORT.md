# SC-08 真实 Prompt 数据接入验收

2026-09-20。本轮补齐执行证据、四阶段事实转换和 Demo 消费链路；未修改四份最终 Prompt，也未修改八份原始 request/response。

## 模型执行来源

此前项目文件只声明使用 GPT-5.6 Sol。本轮找到实际 Codex 宿主日志：任务 `01a0bcde-b495-7a63-8189-f60b315c0ea8`（`/root/run_sol_audit`），宿主 `turn_context.model=gpt-5.6-sol`。日志记录了读取四份最终 Prompt、读取 Excel/OCR、查看 PDF 渲染图、按 P1→P2→P3→P4 顺序产生八份文件。

`execution-evidence.json` 摘录宿主模型元数据及模型产生的文件写入调用，不包含私有思考或凭据。`verify_sol_execution.py` 从这些调用重建八份 JSON 并逐份比较当前文件；本机存在原始日志时还校验日志 SHA-256 和摘录对应行。

执行形态是同一 Sol 模型任务顺序完成四阶段，**不是四个独立 API 请求**。P2 在进入 P3 前曾由同一模型自行修正；本轮没有替模型修改结果。已有真实执行可验证，因此复用，不声称本轮重新调用了模型。

## 输入到页面的路径

1. P1 response 的全部25字段、原始行、证据、冲突及共享范围进入 fixture；SC-08 草稿直接使用这些事实，空值只转换为页面的 null。初始委托证据也进入页面。基准值单独保存，不被人工编辑覆盖。
2. P2 response 的原始商品、来源、产地候选、人工标记、包装与重量范围、问题全部保存在 fixture。页面商品池字段取自 P2，箱号不再被旧 mock 自动当作件数。单一产地原文仅用于展示，不在适配器中重新裁决产地优先级。
3. P3 response 决定关系与覆盖状态。程序仅校验客户、输入快照、资源是否可用，建立占用、版本和日志，不再用型号后缀规则推导关系。
4. P4 response 的每个 FieldDecision 原样保存为字段证据。只有 FILL/UPDATE 写值；KEEP、NO_ACTION、CONFLICT 等按模型结果保留。未请求字段保持，NO_EVIDENCE 不转换为核验一致。
5. 一次回放原子产生一个草稿版本和操作事件，两条关系一起应用。重复点击不重复生成。人工确认后才封版并核销。
6. 候选、事实或人工值变化后，旧结果不适用时拒绝回放，提示重新运行 Prompt。解绑撤销关系依赖的 AI 入仓号及当前核验，保留历史记录与人工值。

## 业务理解偏差及最小修正

- 旧 fixture 保存了 P3/P4，但运行时未消费；已改为直接消费。
- 旧转换只读 P3 请求和 P3/P4 响应；已改为读取全部四阶段响应并校验引用、ID、字段集合和请求一致性。
- 旧代码把“基础型号+后缀标记”硬编码为可靠关系；已移除。当前两条关系仅由保存的 P3 输出决定。
- 旧查货 mock 的件数为1；P2 只识别箱号，并未输出商品件数，因此查货件数留空，委托 P1 的件数1不受影响。
- 数量数值相同不等于单位可比。P4 的数量/单位 NO_EVIDENCE 已保留并在页面展示。
- 9.20 KG 表格总毛重与9 KGS板标是范围事实冲突；完整保留并展示，不将任一总重强写到商品行。
- v1.1 PRD允许“更新原委托”；最终 v3 Prompt要求新业务提交新建任务、P1基准不可变。SC-08禁止旧版覆盖基准入口，人工编辑仍可用；其他旧验收场景不在本轮大规模改造范围。
- 旧页面把所有可选空字段也标为缺失；现在仅13个必填字段标缺失。字段详情随已提交版本刷新，避免仍显示匹配前的空入仓号。

## 范围与限制

本轮真实校准覆盖 **SC-08 / 2025YBT010-2** 这一个完整代表场景，两条委托商品与两条查货原始行。其余场景仍为已有基线/合成验收数据，不宣称21个场景全部经过模型执行。现场任意上传、新材料及变更后的重新推理未实现在线模型调用；这是离线真实结果 fixture 的边界。

P2 将 `Origin FAB` 解释为 `PRINTED_COD`、P3 判为完整覆盖，这是保存的模型判断，不是适配器新增规则。如业务复核不认可，应调整输入证据后重新运行模型，不能在 fixture 中手改结论。本样本只调用 P4 VERIFY_FIELDS，没有重量分配需求，不伪造 ASSESS_CALCULATION 结果。
